## Real remote-provider smoke — 2026-10-24 (OpenRouter, DeepSeek)

A real OpenRouter call completed through the engine after fixing a transport
mismatch. Evidence: `docs/briefs/evidence/pilot-prep/openrouter-deepseek-smoke.json`.

| Check | Result |
|---|---|
| Model | `deepseek/deepseek-v4.1-flash` (cheapest fast DeepSeek id in the live catalog) |
| Engine run (in-process, live) | **completed** in 10.7 s; `engine_ok.txt` written with `engine ok` |
| Cost | fractions of a cent (free-model attempts were also made; they looped on tools) |

Root cause found and fixed in the repo: the bundled dsh runtime (SDK 0.2.1rc2)
always calls the Anthropic Messages API (`/v1/messages`) and sends
`thinking: {type: enabled}` **without** `budget_tokens`. OpenRouter rejects that
with `400 Invalid Anthropic Messages API request`; a minimal body returns 200,
removing `thinking` returns 200, and adding `budget_tokens` returns 200. The
repo already had a transport patch for tests
(`section4/tests/fixtures/openrouter.patch.yml`), but it was not deployable.
Now shipped as `deploy/patches/openrouter.patch.yml`, mounted read-only into the
orchestrator at `/opt/harness/patches`, with `DSH_PATCH_FILES` passed through
Compose and documented in `.env.example`/README.

Still not covered: a container-isolated tool-using run against a remote
provider, token-usage accounting through the patched transport (`usage` null),
and an end-to-end orchestrator run through the full Compose stack with a real
model.
