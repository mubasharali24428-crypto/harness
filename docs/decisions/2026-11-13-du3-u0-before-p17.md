# Decision: D-U3 — U0–U3 before P-17, or P-17 first on the old UI

**Date:** 2026-11-13 · **Status:** ACCEPTED by the decision owner (Mubashar Ali, in session), 2026-11-13.
**Resolves:** UI overhaul plan §6 D-U3; FUTURE PLAN 2.0 §5A Monday decision.

## Context

P-17 is the scoped read-only role and client trust portal (U4). The UI plan recommends building
U0–U3 first so the portal is a skin over the new system rather than a second UI built on the old
stylesheet.

## Options

1. **U0 first, then U1–U3, then P-17 as U4.** Recommended. The shared shell, tokens and primitives
   exist before the portal; the portal does not create a parallel visual language.
2. **P-17 first on the old UI**, then retrofit the new system. Earlier client-facing surface, but
   it guarantees a second migration and a second accessibility pass.

## Recommendation

**Option 1.** P-17's backend role work can proceed independently; only the portal UI waits for U0.
This keeps the week's frontend work on one system and avoids building the portal twice.

## Consequences if accepted

- U4 stays scoped, not built, until the P-17 role exists.
- U0–U3 are the week's build surface; the portal reuses their shell, tokens and evidence patterns.
- If a design partner needs the portal sooner, the owner can revisit this decision with a dated
  exception rather than silently forking the UI.

**Owner decision:** ACCEPTED — Option 1 (U0 first, then U1–U3, then P-17).
**Date:** 2026-11-13 · **Rationale:** as recommended; no divergence.
