# Glossary — project vocabulary as implemented

Canonical definitions for the platform's core nouns. Each entry states what
the thing *is in the code today* (file paths are the proof, not aspiration).
User-facing docs and UI copy must use these terms per the Terminology table
in [`README.md`](../README.md); historical documents are not retroactively
rewritten.

| Term | Definition as implemented |
|---|---|
| **run** | One end-to-end execution of an approved plan. Materialized as a row in `agent_runs` with a lifecycle driven by the Section 4 state machine (`section4/src/harness_orchestrator/state_machine.py`: `idle → planning → awaiting_plan_approval → executing → paused → awaiting_done_signal → reviewing → blocked / pr_opened / done`). Queue presence is a **claim** (below); events stream on the bus; cost accrues to metering (`run_metering.py`). List/read API: `GET /api/v1/orchestrator/runs` (+ `/{id}` aggregate). Not "job", "task", or "execution". |
| **plan** | The agent's proposed approach for a run, frozen as `AgentPlan` in `contracts/src/harness_contracts/plan.py`. Human approval is mandatory before any execution: plan-gate routes under `/api/v1/orchestrator/plans` (`plan_gate.py`) gate propose/approve/reject by role (admin/engineer decide; viewer/guest → 403), store the durable decision on `agent_plans.version` with compare-and-swap (409 `PLAN_ALREADY_DECIDED` on races), and are audited. Plan states: `proposed/approved/rejected/executing/paused/awaiting_done_signal/reviewing/blocked/pr_opened/done`. |
| **brief** | An `EngineeringBrief` (`contracts/src/harness_contracts/brief.py`) produced in the Meeting Area from meeting discussion — requirements, constraints, acceptance criteria, risks, open questions; status `draft` until approved. Approved briefs seed plan proposals ("brief → plan" is step one of the hero journey). |
| **meeting** | A Section 6 collaboration session where humans and the engine draft briefs. Surface: `/api/v1/meetings/*` (`section6/src/harness_meeting/`, port 8006) + section7's Meeting Area UI. `@ai` mentions call real models through Section 3 using team BYO keys (regex stub only as honest fallback); brief generation is rate-limited (budget hook). |
| **claim** | A worker's lease on a queued run: one row per run in `run_claims` (`section1/migrations/0006_run_claims.sql`; state `queued/running/orphaned`). Claims are taken atomically with `SKIP LOCKED`, kept alive by heartbeats every ~10s, and expire via `HEARTBEAT_TIMEOUT_SECONDS` (default 90s = 9 missed beats): the DB-clock zombie reaper (`service.py reap_zombies()`) releases timed-out claims, moves the run to `blocked`, and emits an honest `engine_failed {reason: heartbeat_lost}`. |
| **checkpoint** | Doctrine term for an agent writing uncommitted work + a short state note to disk so a replacement can resume cleanly (mission-command doctrine, `docs/doctrine/mission-command-doctrine.md`; degraded-mode runbook). Also used for the integration suite `integration/test_checkpoint1.py`, which checks one full event→run flow against real Postgres. Not a UI feature; do not promise "restore points". |
| **ticket** | Short-lived WebSocket credential: `POST /api/v1/ws-ticket` mints a single-use, 30-second, project-bound ticket (`ephemeral.py WS_TICKET_TTL_SECONDS = 30`, table `ws_tickets` from migration 0005). Since M15-W5-S2 each ticket is also bound to the issuing client (sha256(UA+IP)[:16] fingerprint, migration 0025): upgrades from another host die with 4403 `TICKET_FINGERPRINT_MISMATCH`; the optional `X-WS-Fingerprint` header gets a one-release grace window. Exists so long-lived bearer tokens never sit in URLs. |
| **envelope** | Two frozen wire shapes, both owned by `harness_contracts`: (1) the error envelope — every non-2xx returns `{"error": {"code", "message"}}` (`api.py error_body()`; legacy `detail` mirror during back-compat; see [api-versioning.md](api-versioning.md)); (2) the event envelope — the one WebSocket frame shape `{type, payload, ts, seq, projectId, runId}` pushed by the bus (`events.py EventEnvelope`), replayed after gaps via `afterSeq`. |
| **no-oracle** | Security property of cross-tenant reads: an unknown id and another team's id produce byte-identical answers (normally 404), so probing reveals nothing about existence. Enforced across sections since M13-G5a (`teams_api.py`, `invites.py`, runs routes); grep for "no-oracle"/"existence oracle" to find the sites. |
| **hero journey** | The canonical happy path a user drives end-to-end: login → create project → meeting → message → brief → plan proposal → approve → run → detail → review (draft PR), extended with the OTP login flow. Automated as the Playwright E2E spec `section7/e2e/journey.e2e.ts` (M13-H3a, H-014), runnable via `make e2e` against the compose stack. |
| **project** | The unit of work a team runs agents against: one row in `projects` (`section1/migrations/0001_initial.sql`), owned by exactly one team. Created with `POST /api/v1/projects {name}` (201 → `{id, name, repoFullName}`, optionally bound to a GitHub repo); scoped container for runs, plans, events, checkpoints, and the per-project rules document (see [extensions.md](extensions.md)). There is no DELETE /projects — deactivation is data-level only today. Not "workspace", not "repo" (a project may reference a repo but is not one). |
| **sandbox** | Section 5's execution confinement for agent work (`section5/src/harness_sandbox/`, port 8005): commands run against an allow-list of first tokens, one command per exec call (no shell chaining/piping/substitution — quote-aware scan in `policy.py`), file edits validated against `forbidden_paths`, which are hard constraints no rules text or plan can relax. Violations raise `SecurityPolicyViolationError` and surface as honest failures. AGENTS.md law: "Nothing outside Section 5's allow-list executes." |
| **dry mode / live mode** | The engine's explicit, mutually exclusive postures (`live_mode.py LiveMode`): **dry** (default, `ENGINE_LIVE_MODE=dry`) answers `status:"not_configured"` with the exact env vars needed — it never fakes success; **live** requires `DEEPSEEK_API_KEY` (+ `DEEPSEEK_BASE_URL` for OpenAI-compatible endpoints, local Ollama counts) and `DSH_MODEL`, and every run then goes through the deepseek-harness-sdk with real token metering. A third posture exists for tests/load: an injected `backend_runner` callable ([extensions.md](extensions.md) seam 1) reports `"engine": "injected"`. Mode resolution fails loudly on typos/placeholder credentials — never silently downgrades. |
| **KeyVault** | The at-rest secret encryption primitive in frozen contracts (`contracts/src/harness_contracts/security.py`): Fernet keyed by sha256 of `HARNESS_MASTER_KEY`, encrypting provider API keys and GitHub tokens before they hit storage; decryption happens server-side only and never enters logs or model context (AGENTS.md law). Only hints are ever exposed (`KeyVault.hint()` → `…last4`). Wrong master key ⇒ `ValueError("secret decryption failed")` — rotate the master key and old ciphertexts become unreadable. Booted without a master key, identity crash-loops by design. |
| **brief-gate vs plan-gate** | Two different human approval points, do not conflate: the **brief-gate** is the Meeting Area's approval of a drafted brief — `POST /api/v1/meetings/{meetingId}/brief/{briefId}/approve` (`section6/src/harness_meeting/api.py:406`), moving the `EngineeringBrief` from `draft` to `approved` so it can seed plan proposals. The **plan-gate** is the orchestrator's mandatory pre-execution approval — propose/approve/reject under `/api/v1/orchestrator/plans/*` (`plan_gate.py`), role-gated, CAS-guarded, audited. Brief-gate approves *what to build*; plan-gate approves *how the agent will do it* and is the only gate standing between a proposal and code execution. |
