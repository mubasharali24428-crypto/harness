# A3-S1 — Precise browser and guarded computer interaction

Worktree `harness-a3` (branch `codex/harness-a3`, HEAD `31bf407`). Nothing committed.

## What exists (all owned paths)
- `workers/browser/` — TypeScript/Playwright worker: typed observations (DOM refs, frames, viewport/DPR, screenshot artifacts with sha256), actions (navigate/click/type/press/scroll/hover/select/waitFor/screenshot), target resolution (ref/selector/role/text/point; ambiguity and stale-ref rejection), postconditions (polled), isolated persistent per-(team,project,run) sessions, one-time approvals, S5 capability tokens, SSRF/egress policy, HAP/1 HTTP adapter (`src/server.ts`).
- `workers/desktop/` — guard (`DesktopController`) + opt-in `MacOSAdapter`.
- `section5/src/harness_sandbox/browser_cap.py` (+ test) — Python minting side of the capability token; golden fixture is generated by Python and verified by the TS worker (and re-minted byte-for-byte).

## Defects found and fixed this session (pre-existing partial work was red)
1. Test harness imported the fixture at the wrong path; no `.d.ts` for `.mjs`.
2. `targets.ts` descriptor `by` duplicated (TS2783).
3. Ref targets built locator `[data-harness-ref="f0:e5"]` but the DOM attribute is `e5` → every ref click hung until timeout. Fixed.
4. External-write auto-detection only ran for ref targets; role/selector/text clicks followed external links and failed post-hoc. Now detected for all, before clicking.
5. Postconditions and `waitFor` were instantaneous; now polled (3 s / caller timeout).
6. Missing capability token raised TypeError → `failed`; now `denied` (fail closed).

## Limits — not claimed
- HTTP auth was tested against a local stub of S1 `/api/v1/me` + `/api/v1/projects`; not against live Section 1.
- The live SDK→S5→browser path is not wired (needs A2/A5). Capability secret is a scoped shared secret, not a vault key.
- Desktop: real macOS input/capture was **not run** (it would drive/capture the user's actual screen). Guard logic and command construction only.
- `state.json` is not encrypted at rest.
- Approval endpoint is admin-only; cannot distinguish a human from an agent holding an admin token.
