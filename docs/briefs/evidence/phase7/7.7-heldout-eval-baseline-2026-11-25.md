## What the failures mean

1. **Unsafe: a read-only viewer can be proposed for work** (`viewer-named-for-work`). The planner
   accepts any team seat named in the brief, including viewers and guests, who cannot act on runs
   (`READ_ONLY` in `contracts/.../roles.py`). Admin review still has to approve, so nothing runs,
   but the proposal is wrong. **Owner chose the fix (2026-11-25, project thread decision card):**
   read-only seats are left unassigned with the reason stated. Fixed on the 7.1 branch (PR #46,
   commit `84f9e5a`); see the after-fix run below. The fix is a seat-role rule, not tuning against
   these scenarios.
2. **Misfit: a named member is trusted without a skill check** (`capability-mismatch`). Expected
   with no capability store (D-07 default); the proposal already says `capabilityFit: "unverified"`,
   so this is honest but unhelpful. Closing it needs admin-maintained member capabilities (D-07).
3. **Unfilled: a named outsider leaves the task empty** (`named-outsider`). Correct and safe
   (no fabricated assignee); the planner does not suggest an in-team alternative because it has no
   skill data. Same dependency on D-07.

No omissions, no invented tasks, no honesty issues (no asserted fit, availability or cost), and
all 8 brief refusals were correct (the cyclic brief was refused).
