## Why this slice

FUTURE PLAN 2.0 §12 lists 7.1 first: "Structured project brief: goals, constraints, roles,
capabilities, dependencies, priorities, outputs, acceptance criteria. Done when: schema reviewed;
unknown skills and absent members represented honestly." Sprints 2–4 built C-01…C-05 and the C-07
note rule (`assignment_plan.py`, migration `0078`), but the brief had no roles, capabilities,
priorities or outputs, and a brief with a **dependency cycle was accepted**. This slice closes
those gaps.

## Gating check

Phase 7 follows Phase 6 in the dependency order, and Phase 6 build waits on P-D7 (DEFERRED).
7.1 is not gated: it changes the shape of an admin-only proposal and adds no visibility, no
lifecycle, no dispatch and no authority. Items that **are** effectively gated:

- 7.4 / 7.5 (deliver each task's authorized context to its assignee; shared dependencies) need
  Phase 6 member-level visibility (gap map G3, G6) to mean anything beyond today's `/mine`.
- 7.6 (agents attached to assignments) needs D-06 and the Phase 6 assignment lifecycle (G8).

## What changed

Backend `section4/src/harness_orchestrator/assignment_plan.py`:

- Brief: `roles[]` (`name`, `capabilities[]`), `outputs[]`. Task: `priority`
  (`high | medium | low`), `outputs[]`, `requiredCapabilities[]`. All optional; old briefs valid.
- 422 `BAD_BRIEF` for: a dependency cycle (message names the path, e.g. `a -> b -> a`), a
  self-dependency, duplicate role names, a task naming a role the brief did not declare (only when
  the brief declares roles, so pre-7.1 free-text roles still work).
- Each proposed assignment adds `assigneeStatus` (`member | not_a_member | unnamed`), `priority`
  (`unspecified` when absent), `requiredCapabilities` (role capabilities plus the task's own,
  de-duplicated), `capabilityFit: "unverified"`, `availability: "unknown"`. When unassigned,
  `missingExpertise` lists the role and every required capability.
- Admin edit keeps `assigneeStatus` in step with the reassignment.
- `/mine` adds `priority` and `outputs` of the caller's **own** tasks only. Versions stored
  before this change (no new keys) still serve.

Frontend `section7/app/projects/[projectId]/planning/`: optional TS fields; admin table gains a
Priority column, "Needs … (fit not verified)" and a distinct "named person is not a team member"
label; member view shows own priority and outputs.

## Honesty rules kept

- No capability or availability is ever asserted. There is no admin-maintained capability store
  (D-07 default), so even a named member's fit is `unverified`.
- A named person who is not on the caller's team is reported only as "not a current team member";
  nothing about any other team is described (test asserts `team-b` never appears).
- Capability labels grant nothing; nothing dispatches (D-05). No migration (the brief and
  assignments are stored as JSON text in `0078`), no `contracts/` change, no flag.

## Follow-up: read-only seats (found by the 7.7 evaluator, PR #47)

The held-out evaluation showed the planner would propose a **viewer** for work when a brief named
one. Viewers and guests are read-only (`contracts/.../roles.py` `READ_ONLY`) and cannot act on runs,
so such a task is now proposed UNASSIGNED with `assigneeStatus: "read_only"` and the reason stated,
and an admin edit that assigns a viewer or guest is 422 `BAD_REASSIGN`. Role comparison is
case-insensitive because ORM writes store enum names (`VIEWER`). **Owner confirmed** this rule on
2026-11-25 (project thread decision card: "Yes, leave them unassigned").
