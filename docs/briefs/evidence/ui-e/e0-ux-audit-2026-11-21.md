## What already passes (so later phases don't re-litigate)

- Axe WCAG 2.2 A/AA/21AA/22AA: **0 violations** on /runs, run page, /settings.
- No horizontal scroll at 375 on run and diff; both themes render; reduced-motion honoured in captures.
- Reload on `?pane=diff` restores the pane and the reviewed control; back/forward params intact.
- Honest labels verified live: REPLAY banner, "Spend < $0.01 · Estimated $0.01", verdict card "not recorded is not a pass", "Advisory summary … Not an approval to merge", request-changes disabled until text exists.
- Keyboard basics: ⌘K palette on every walked surface, g-then-h/g-then-r, skip-link, keyboard-help panel.
- LCP 44–208 ms and approximate INP ≤ 32 ms on all 34 measured route/profiles — headroom for E1's system to spend on polish.

## New backend gaps found (extend §6)

| Gap | Effect on UI | What to do |
|---|---|---|
| Demo-seeded project has no tree endpoint data (`/projects/:p/tree` 404 on RC) | Tree page renders without data on every demo run | Report + decide: demo tree fixture server-side, or tree page hidden for repo-less projects with an honest empty state |
| Plan pane fetch 404s on the RC demo run (exact endpoint to be named in E2) | Plan pane shows without plan data on RC demo runs | Identify the 404ing call in E2; report the endpoint/contract needed |
| Onboarding readiness requests an unreachable service on RC (connection refused) | First-run checklist can't load its signals on RC | Identify the port/service onboardingApi calls that RC does not expose; report before E6 |
| Demo cost data carries a model literally named `stub` | Cost breakdown shows "stub" as a model name | Either seed a plausible model label in the demo data or label the row "demo model (stub)" in the UI |

Method note: findings 1–18 are from rendered text and runtime capture (screenshots committed beside this report), not code reading. The scripted detector pass (e0-audit-walk.mjs) recorded zero axe/console/overflow failures; the issues above were surfaced by reading rendered content and the perf numbers — i.e. the app is *correct and accessible* but not yet *calm and plain-spoken*, which is exactly this prompt's mandate.
