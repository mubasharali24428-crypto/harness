# API Versioning & Compatibility

How this platform versions its HTTP/WS surface, how the frozen contracts
package evolves, and how parameters are retired. The normative source is
[`contracts/api-conventions.md`](../contracts/api-conventions.md) (frozen —
owned by Section 1); this document explains the law and shows the worked
example. When the two disagree, the frozen file wins.

## The `/api/v1` convention

- **One prefix for every backend route: `/api/v1/...`.** Every section's
  router declares it (`API_PREFIX = "/api/v1"` in
  `contracts/src/harness_contracts/api.py`; each router pins it: identity
  `prefix="/api/v1"`, orchestrator `/api/v1/orchestrator`, models
  `/api/v1/models`, meeting `/api/v1/meetings`, review, sandbox
  `/api/v1/sandbox`, onboarding `/api/v1/onboarding`). No versionless alias
  routes exist; a URL without `/api/v1` is not part of the API.
- JSON over HTTPS only. Auth is `Authorization: Bearer <token>` issued by
  Section 1's `/auth/login` (WebSocket upgrades use one-time 30s project-
  bound tickets from `POST /api/v1/ws-ticket` instead of long-lived tokens
  in URLs).
- Success bodies are the resource object with camelCase keys; resource
  naming is plural nouns with kebab-case path segments; non-CRUD actions
  are `POST /resource/{id}/{action}` (e.g. `POST /runs/{id}/pause`).
- Pagination (when needed): `?limit=&cursor=` returning
  `{"items": [...], "nextCursor": ...}`.
- WebSocket endpoint: `GET /api/v1/ws/{projectId}?afterSeq=<int>` (+ ticket);
  the server pushes exactly the frozen `EventEnvelope` shape.

## Contracts versioning law

Everything shared between sections lives in the frozen package
`harness-contracts` (directory [`contracts/`](../contracts/) at the repo
root). AGENTS.md states the rule in one line: *breaking a contract without a
version bump + consumer mock updates in the same commit is unforgivable.*

**The version lives in four places and they must move atomically** (one
commit):

1. `contracts/pyproject.toml` → `[project] version`
2. `contracts/src/harness_contracts/__init__.py` → `__version__`
3. `contracts/ts/types.d.ts` header comment (`// TS mirror of
   harness_contracts vX.Y.Z`) — the TS mirror for frontend sections,
   regenerated by `python3 contracts/ts/generate.py --check`
4. the installed distribution metadata (`importlib.metadata.version("harness-contracts")`,
   i.e. re-run `pip install -e ../contracts` after bumping)

This 4-way equality is enforced by a real collected test
(`section1/tests/test_version_pin_conformance.py`, revived in M13-H3b), so
source-tree divergence fails CI rather than rotting quietly. Consumer floor
pins (`harness-contracts>=X` in section pyprojects) are checked to stay
satisfiable.

Current version: **0.3.0**.

Bump classes:

- **Additive change** (new event type, new optional field): allowed without a
  major bump — precedent: contracts 0.3.0 added `engine_completed`/
  `engine_failed` as an additive wave-6 extension. Additive does not mean
  unversioned: still bump the patch/minor and update the TS mirror.
- **Breaking change**: bump the version AND update every consumer's mocks in
  the same commit. There is no deprecation shim inside `contracts/`; the
  freeze means consumers compile against exactly what ships.

## Deprecation policy (HTTP params & payloads)

The API surface follows a **one-release acceptance window**: when a wire
shape is superseded, the legacy form keeps working but is documented as
deprecated at the point of implementation, and it is removed no earlier than
the next release. Callers get at least one full release to migrate; removal
is never silent within a release.

Worked example — runs list pagination (M14-F3a):

- Before: `GET /api/v1/orchestrator/runs?offset=…&total` style offset paging.
- After (frozen convention shape): keyset cursor paging —
  `GET /api/v1/orchestrator/runs?limit=&cursor=` →
  `{"items": [...], "nextCursor": ...}` where `nextCursor` is an opaque
  base64 token marking the last row of the page; `null` ends the collection.
- Transition behavior, implemented in
  `section4/src/harness_orchestrator/runs_index.py`: the legacy `?offset=`
  parameter is **accepted but ignored** for one release ("deprecated
  one-release window: accepted, never applied"), `total` was dropped from
  the payload (keyset paging has no stable total without a per-request
  COUNT), and pages remain stable under inserts because the keyset predicate
  orders by the same deterministic `(created_at DESC, id DESC)` the offset
  pager used.
- Same policy applied on the WS side in M15-W5-S2: the `X-WS-Fingerprint`
  header is optional for one release — absent ⇒ warn-log + allow (legacy
  clients keep working); present + wrong ⇒ reject. Server-side validation
  runs regardless, so security never depends on clients migrating.

A parallel discipline applies to response fields that must keep old clients
alive: error responses mirror the envelope under both `error` and the legacy
top-level `detail` key (see below) — back-compat mirrors are removed on the
same one-release clock.

## Error envelope contract

Every non-2xx response from every section returns the frozen contract shape:

```json
{"error": {"code": "<MACHINE_CODE>", "message": "<human-readable>"}}
```

- Source of truth: `error_body()` in
  `contracts/src/harness_contracts/api.py`; OpenAPI documents it via the
  `ErrorEnvelope` response model (`responses={...}` islands hardened across
  S1/S3/S4/S6 in M13-G5a).
- Back-compat mirror (M12-W2.1 lane F1): handlers also return the same body
  under top-level `"detail"` —
  `{"error": {...}, "detail": {"error": {...}}}` — so pre-envelope clients
  keep parsing during the migration window.
- Coverage: FastAPI `RequestValidationError` (422s used to escape as bare
  `{"detail": [...]}`), Starlette `HTTPException`s (plain-string details
  normalized), and unhandled exceptions (500s return the envelope, never a
  stack trace).
- Machine codes are SCREAMING_SNAKE tokens (`LAST_ADMIN`, `PLAN_ALREADY_DECIDED`,
  `INVALID_CURSOR`, `TICKET_FINGERPRINT_MISMATCH`, `NOT_CONFIGURED`, …) and
  are stable API surface: renaming one is a breaking change subject to the
  versioning law above.
- Cross-team probing gets identical answers for unknown vs. foreign ids
  (404 with no existence oracle) — that is an information-disclosure rule,
  not an exception to the envelope.
